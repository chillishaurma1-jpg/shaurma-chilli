# Управление меню Chilli

## Запуск

1. В папке лендинга дважды нажмите `Управление меню.cmd`.
2. В браузере откроется панель. Окно запуска оставьте открытым, пока работаете.
3. Выберите товар слева; меняйте поля справа. Новую фотографию выберите кнопкой «Выбрать фото».
4. Нажмите «Сохранить», чтобы записать изменения на компьютере.
5. Нажмите «Предпросмотр», чтобы увидеть сохраненную версию сайта.
6. Нажмите «Опубликовать», чтобы сохранить и отправить меню на сайт. Дождитесь надписи «Опубликовано на сайте». Обычно обновление занимает некоторое время.

Для остановки закройте окно запуска или нажмите в нем Ctrl+C. Если закрыть только вкладку, служба останется работать до закрытия окна запуска. Повторный запуск открывает новую панель; сохранять одновременно в разных вкладках не нужно.

## Товары и категории

- Кнопка с плюсом над списком создает товар.
- Кнопка с папками открывает категории: здесь можно добавить или переименовать категорию и изменить порядок стрелками. Удалить можно только пустую категорию.
- Стрелки над формой меняют порядок выбранного товара в общем списке.
- «Показывать на сайте» позволяет временно скрыть товар, не удаляя его.
- «Популярное» добавляет товар в первую вкладку меню.
- Пустая цена доставки означает «нет в доставке». Цена самовывоза обязательна.
- Объем показывается только в категориях «Напитки» и «Соусы».
- При загрузке принимаются PNG, JPEG и WebP до 20 МБ. Панель создает уменьшенный WebP, сохраняя пропорции; исходное фото не меняется.

Google-таблица больше не обновляет меню автоматически. Рабочие данные находятся в `menu.json`; файл `menu-data.js` создается для сайта автоматически. Не редактируйте эти файлы вручную во время работы панели.

## Если появилась ошибка

- «Меню изменено в другой вкладке»: сохраните нужный текст отдельно, обновите страницу и повторите правку поверх свежих данных.
- «Файл изменен на GitHub»: публикация остановлена, чтобы не затереть другую версию. Локальное меню сохранено. Потребуется сравнить версии; не удаляйте рабочую копию публикации и не выполняйте принудительную отправку.
- «Не удалось выполнить операцию GitHub»: проверьте интернет и повторите «Опубликовать». Если вход на этом компьютере больше не действует, его нужно восстановить в GitHub CLI командой `gh auth login` (секреты не вводятся в панель).
- «Отправлено на GitHub», но еще нет подтверждения сайта: дождитесь завершения проверки. Если проверка закончилась без подтверждения, повторное «Опубликовать» проверит ту же версию без лишнего commit.
- Если браузер сообщает, что нет доступа: откройте панель заново через `Управление меню.cmd`. Не пересылайте адрес панели другим людям.

## История и восстановление

Каждая публикация меню сохраняется в истории репозитория `chillishaurma1-jpg/shaurma-chilli`. Commit — это сохраненная версия файлов. Вернуть прежнее меню можно отдельным обратным commit, не стирая историю. Исходная версия перед переносом меню сохранена локально в `6657a7c7`.

Папка `.admin-state` содержит локальные служебные данные и не отправляется на сайт. Текущая настроенная рабочая копия публикации — `.codex-backups/deploy-shaurma-chilli`; на новом компьютере панель создаст `.admin-state/publish`. Не меняйте эти папки вручную во время публикации.

Для разработки: `node --test tests/admin-*.test.cjs` и `node tests/check-site.js`. Браузерная проверка: `node tests/admin-ui.cjs`; Playwright берется из существующей локальной установки или переменной `PLAYWRIGHT_PATH`. Иконки Lucide 0.468.0 поставляются локально; лицензия находится в `admin/LUCIDE-LICENSE`.
