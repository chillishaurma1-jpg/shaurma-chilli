# Локальное управление меню Chilli

Дата: 23 октября 2026 года.

## Назначение

Владелец меняет меню с этого компьютера через форму в браузере, без изменения кода и без отдельного интернет-сервера. Панель запускается двойным щелчком по `Управление меню.cmd` в папке проекта. Посетители сайта не получают доступ к редактору.

## Интерфейс

Список товаров с поиском и фильтром категории; форма выбранного товара с названием, подписью, ценами самовывоза и доставки, категорией, объемом, фотографией, признаками «Показывать на сайте» и «Популярное». Пустая цена доставки означает отсутствие доставки. Объем отображается только у напитков и соусов.

Можно добавлять товары, скрывать их, менять порядок, создавать и переименовывать категории. Удаление товара требует подтверждения. Фотография выбирается с компьютера, предварительно показывается и преобразуется в WebP с ограничением размера; оригинальные пользовательские файлы не перезаписываются.

Команды: «Сохранить», «Предпросмотр», «Опубликовать». Несохраненные изменения отмечаются; закрытие страницы вызывает предупреждение. Публикация включает сохранение после проверки данных. Предпросмотр показывает локально сохраненную версию. Ошибки показываются понятным текстом, поля с ошибками выделяются.

## Данные и сайт

Основной источник меню — `menu.json`: версия формата, упорядоченные категории и товары с постоянными идентификаторами. Начальное содержимое переносится из текущего `script.js` без изменения цен и состава. Google-таблица после перехода не синхронизируется автоматически: новые изменения делаются в панели.

Для готового сайта из JSON создается `menu-data.js`, подключаемый перед `script.js`. Это сохраняет работу статического сайта без запроса к сторонней базе. При публикации проверяется совпадение исходных и сгенерированных данных. Пользовательский текст безопасно выводится на странице, включая кавычки и специальные символы.

## Локальная служба

Node.js уже установлен. Служба слушает только `127.0.0.1` и не занимает занятый порт. Запуск открывает браузер; остановка выполняется из окна запуска. Для запросов изменения используются случайный ключ сеанса и проверка Origin/Host, чтобы посторонний сайт не мог отправить команду публикации. Доступ к файлам ограничен нужными файлами проекта; произвольные пути, SVG и исполняемые загрузки не допускаются. Ключ сеанса не записывается в Git.

## Сохранение и публикация

Сохранение проверяет структуру, непустые названия, категории, неотрицательные цены и существование фотографий, затем заменяет файл атомарно. Одновременная запись блокируется; устаревшая открытая вкладка не перезаписывает более свежую версию.

Публикация использует существующий удаленный репозиторий `chillishaurma1-jpg/shaurma-chilli` и настроенный на компьютере доступ Git. Выполняется последовательно, без параллельных публикаций. Проверяются удаленная версия и чистота отдельной рабочей копии публикации. При конфликте процесс останавливается без сброса файлов и без принудительной отправки.

Отправляются только файлы меню, необходимые изменения подключения и используемые новые фотографии. Редактор, временные данные, дизайнерские исходники и учетные данные в публичный сайт не попадают. Изменения сайта других пользователей не перезаписываются. После commit и push проверяется опубликованная версия данных; до подтверждения показывается «Ожидает публикации», а не «Опубликовано». При сбое сохраняется локальный результат и доступна повторная попытка.

## Восстановление

Перед переносом существующего меню создается Git-контрольная точка только нужных файлов, без посторонних изменений. Значимые этапы сопровождаются короткими записями в `.codex-history`. Каждая публикация меню сохраняется отдельным commit. Большие исходники фотографий не добавляются в историю автоматически. Рабочие данные панели и зависимости исключаются через `.gitignore`.

## Проверка готовности

Проверить перенос всех 54 текущих позиций и популярного списка, редактирование и сохранение цены после перезапуска, скрытие и добавление товара, изменение категории и порядка, замену фото, предпросмотр, специальные символы, отклонение некорректных данных, внешнего запроса и выхода за папку проекта. Проверить конфликт сохранения, сбой Git и повторную публикацию. Выполнить существующую проверку сайта и визуальную проверку панели в браузере. Реальный push и появление версии на сайте проверяются отдельно от локальных тестов.

## Границы

В первой версии нет доступа с телефона через интернет, нескольких пользователей, управления заказами и автоматической синхронизации Google-таблицы. Существующие блоки сайта, отзывы, обложки и аналитика сохраняют свое поведение.
