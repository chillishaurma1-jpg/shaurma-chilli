# Local Menu Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after plan approval. Steps use checkbox syntax for tracking.

**Goal:** Дать владельцу локальную форму управления товарами, фото и категориями с публикацией на существующий сайт.

**Architecture:** Node.js обслуживает редактор только на loopback-адресе. `menu.json` хранит все товары; генератор создает статический `menu-data.js`. Изолированная рабочая копия публикации отправляет проверенные изменения в существующий GitHub Pages репозиторий.

**Tech Stack:** Node.js, стандартные модули HTTP/crypto/fs/child_process, HTML/CSS/JavaScript, Git; преобразование фотографий через Canvas браузера в WebP.

**Spec:** `docs/superpowers/specs/2026-10-23-local-menu-admin-design.md`

## Global Constraints

- Служба слушает только `127.0.0.1` и не занимает занятый порт.
- Посетители сайта не получают доступ к редактору.
- Google-таблица после перехода не синхронизируется автоматически: новые изменения делаются в панели.
- Объем отображается только у напитков и соусов.
- При конфликте процесс останавливается без сброса файлов и без принудительной отправки.
- Редактор, временные данные, дизайнерские исходники и учетные данные в публичный сайт не попадают.
- Изменять только активный проект; не включать посторонние грязные файлы в commits.

## Review Focus

1. Кавычки, HTML и Unicode в названиях: безопасный вывод без изменения текста.
2. Две вкладки: устаревшее сохранение отклоняется, свежая версия остается целой.
3. Посторонний сайт и пути `../`: доступ к изменениям и произвольным файлам закрыт.
4. Отсутствие сети или изменение GitHub другим пользователем: нет потери локальных или удаленных данных.
5. Обрыв после push: повторная попытка проверяет версию, не создает дублирующую публикацию и не сообщает ложный успех.

### Task 1: Данные меню и перенос

**Files:** `admin/menu-store.cjs`, `admin/migrate-menu.cjs`, `menu.json`, `menu-data.js`, `script.js`, `index.html`, `tests/admin-store.test.cjs`, `tests/check-site.js`, `.gitignore`, `.codex-history/2026-10-23-menu-migration.md`.

**Interfaces:** `validateMenu(data, root)` возвращает нормализованный документ `{version:1,categories:string[],items:Item[]}` либо ошибку; `generateMenuScript(data)` возвращает исходник с `window.CHILLI_MENU_DATA`; `loadMenu(root)` возвращает `{data,revision}`; `saveMenu(root,data,expectedRevision)` проверяет revision, атомарно сохраняет JSON и генерируемые данные под блокировкой. Item: `id,name,subtitle,volume,category,pickupPrice,deliveryPrice,image,visible,popular`; порядок определяется массивами.

- [ ] Зафиксировать исходные `index.html`, `script.js`, `style.css`, действующие тесты и необходимые публичные assets в контрольном commit после проверки размеров. Не трогать дизайнерские исходники; обеспечить восстановление меню до переноса.
- [ ] Написать тесты валидатора: повторный id, пустое имя, неизвестная категория, отрицательная/нечисловая цена, отсутствующее фото, выход за assets, скрытые товары, специальные символы. Запустить `node --test tests/admin-store.test.cjs`, подтвердить ожидаемую ошибку отсутствующего модуля.
- [ ] Реализовать store и разовый перенос через ограниченный JS-контекст существующих констант MENU/POPULAR_ITEMS. Сохранить 54 позиции, цены, категории, фотографии и признаки популярности; добавить постоянные id.
- [ ] Подключить `menu-data.js` перед `script.js`. Использовать видимые товары и упорядоченные категории; популярность привязать к id/полю товара. Экранировать динамический текст и атрибуты в карточках и модальном окне. Сохранить текущую аналитику и правила отображения объема.
- [ ] Проверить перенос сравнением старых и новых данных, сохранение после перезапуска, конфликт revision и отсутствие записи при ошибке. ### Task 2: Локальная служба и редактор

**Files:** `admin/server.cjs`, `admin/public/index.html`, `admin/public/app.js`, `admin/public/style.css`, `Управление меню.cmd`, `tests/admin-server.test.cjs`.

**Interfaces:** `createAdminServer({root,publisher})` создает HTTP-сервер. `GET /api/menu` возвращает snapshot store; `PUT /api/menu` принимает `{data,revision}`; `POST /api/images` принимает ограниченный WebP и возвращает `{image}`; `GET /preview/` обслуживает разрешенные публичные файлы; `POST /api/publish` и `GET /api/publication` используют Task 3. Все API требуют сеансовый ключ; запросы изменения требуют точного Origin/Host. Страница получает ключ из URL fragment и сразу удаляет его из адресной строки; ключ остается только в памяти вкладки.

- [ ] Написать и запустить падающие HTTP-тесты: неверный ключ/Origin/Host, traversal и encoded traversal, превышение размера, неподдерживаемая картинка, конфликт revision, чтение запрещенного файла.
- [ ] Реализовать службу с выбором свободного порта через bind port 0; ограничить объем тела запроса и разрешенные статические пути. Загрузки проверять по сигнатуре WebP и допустимому размеру; имена генерировать сервером без перезаписи существующих фото. Запускать браузер через Windows start без интерполяции пользовательских аргументов. Закрытие окна запуска останавливает службу.
- [ ] Сделать интерфейс: список с поиском/категорией и превью; форма товара; управление категориями и порядком; добавление/удаление/скрытие/популярность; пометка несохраненных изменений; полевые ошибки; кнопки сохранения, предпросмотра и публикации. Использовать локально поставленные lucide-иконки с подписями/tooltip и без сетевой зависимости; редактор имеет собственные стили.
- [ ] Реализовать преобразование растрового фото через Canvas до ширины 1200 px, сохраняя пропорции; запретить чрезмерные размеры и объем; показывать результат до сохранения. Не загружать оригинальные большие файлы в Git.
- [ ] Выполнить HTTP-тесты и визуальную проверку браузером: изменение цены, новый товар, новая категория/переименование/порядок, скрытие, специальный текст, загрузка фото, перезагрузка страницы после сохранения. Проверить отсутствие сдвигов/перекрытий на 1366x768 и 430x932. Зафиксировать этап и русское описание истории.

### Task 3: Публикация и восстановление

**Files:** `admin/publish.cjs`, `tests/admin-publish.test.cjs`, `admin/README.md`, `.codex-history/2026-10-23-local-admin-ready.md`.

**Interfaces:** `createPublisher({root,remote,branch,liveUrl,runGit,fetchLive})` предоставляет `start(snapshot)` и `status()`; состояния idle/checking/pushing/waiting/published/failed содержат сообщение и commit. Зависимости Git и HTTP подменяются в тестах. Публикуемый snapshot неизменяемый на время задачи.

- [ ] Написать тесты временных локальных Git-репозиториев: грязная копия, изменившаяся удаленная версия, неудачный push, отсутствие доступа, разрешенный список файлов, две одновременные задачи, повтор после успешного push, несовпадение live-версии. Запустить и подтвердить исходный FAIL.
- [ ] Создать отдельную игнорируемую рабочую копию в `.admin-state/publish`; использовать существующие Git credentials без чтения/сохранения секретов в коде. При первом запуске безопасно получить origin/main. Для изменений `index.html`/`script.js` сверять базовую версию: чужие изменения останавливают публикацию. При несовпадении локальной и удаленной базы не применять принудительный push/reset.
- [ ] Публиковать только `menu.json`, `menu-data.js`, необходимые проверенные изменения подключения и используемые новые assets. Выполнить проверки данных и сайта, commit и push. При сетевой ошибке сохранить commit и дать повторить отправку. Если данные не изменились, не создавать новый commit.
- [ ] Проверять по HTTPS точное содержимое опубликованного `menu-data.js` и требуемые версии подключения. При ожидании GitHub Pages сохранять статус waiting; лимит ожидания переводит в понятное сообщение с возможностью повторной проверки. Предусмотреть таймауты Git/HTTP и ограничение журнала без вывода учетных данных.
- [ ] Проверить launcher двойным запуском, сохранение после перезапуска и работу опубликованного сайта. Реальную первую публикацию выполнить на неизмененном по составу/ценам меню, проверить появление версии на сайте и сохранить commit SHA как отдельное свидетельство. При недоступности credentials отметить это как непроверенное, не заявлять успешную публикацию.
- [ ] Написать короткую русскую инструкцию запуска, сохранения/публикации, остановки и восстановления. Выполнить `node --test tests/admin-*.test.cjs`, `node tests/check-site.js`, синтаксические проверки; провести итоговый обзор diff и безопасности. Стабильную контрольную точку сохранить в GitHub без локальных секретов, редактор не выкладывать в публичные страницы.

## Execution Handoff

Рекомендуется выполнение основным агентом в текущем чате: три задачи последовательно используют один формат меню и один процесс публикации. Перед реализацией требуется подтверждение этого плана. Первая публичная версия сохраняет существующее меню, затем пользователь меняет его через панель.
